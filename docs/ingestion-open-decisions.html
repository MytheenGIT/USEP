Ingestion: decisions and open items

Covers the ingestion layer from the source API to the raw store. Sources: poc-module-spec.md (v0.3), USEP_HLD_v1.0, USEP_LLD_v0.1, semantic_layer_design, and the lead's decision register and open items (docs/claude-project/knowledge/). Rule used: where the documents disagree, the HLD and LLD win. Status tags: decided the owner has chosen. open needs a decision before real data. not built the code does not do it yet.

2. Suggestions on O-01, for the ADR (code unchanged)

PointWhat the code doesSuggestion
When the snapshot is writtenAt fetch, before the pipeline validates anything.Keep. Writing at fetch is the only way to prove what the source said at that time. The cost is that an object rejected later by C-02 validation still has a stored snapshot. State that in the ADR and let quarantine at C-02 mark it.
Redaction before the writeThe writer scans for secrets and personal data and quarantines a hit instead of storing it (nothing is redacted in place).Keep, and write down that "redact" here means "do not store". Two gaps to record. The pattern list is not yet reviewed by security (O-11). Passport, driver's licence and patient-record numbers are not detected because no format is defined anywhere (the writer's own comment says "do not guess").
Skip unchanged contentSame content hash means no new write, and no new event.Keep. Note the one trade-off: a source that changes only in fields outside the raw payload will not produce a new snapshot.
Which versions are keptEvery distinct content version is a separate object, forever.Fine for the pilot. A Jira issue edited 100 times leaves 100 objects, so decide before the pilot whether to keep only the versions a fact or package relies on. That rule needs the fabric writer (C-04), which does not exist yet, so do not build pruning now.

D-07 openSensitive-data pattern list (O-11) and the missing formats.Security review of the list; define passport, licence and patient-record formats or decide to block those fields by other means.Needed before the filter runs on real data. D-08 openFigma DPIA (O-05, ADR-025).Sign-off date.Done in code: Figma file keys are ignored until USEP_INGESTION_FIGMA_DPIA_APPROVED=true. Record the sign-off, then set the flag.Live Figma data.
D-09 openAudit location and retention (O-09, O-12) and the 6-month default in the spec.Spec: 6 months, configurable. Register: 7 years WORM exit (ADR-032).The table is append-only and hash-chained now. The retention job, the periodic hash export to a locked bucket (spec 7.5) and database role privileges are infrastructure choices not made yet. The trigger on Postgres is a stand-in for role privileges.Audit claims at pilot.
D-10 openWrite-once evidence store (HLD 4.5, D5).S3 Object Lock with retention.An infrastructure setting (platform-iac). With the s3 store the service checks the bucket at start-up and logs a warning if versioning or Object Lock is missing; it cannot set them. The file store has no write-once protection at all.Evidence claims.
D-11 openSource rate limits.Confirm each vendor's real limit.Defaults are conservative guesses: Jira 5, Confluence 5, GitLab 10, Figma 1 requests per second. Set them from the vendors' documentation.Tuning only.
D-13 openMay the service read every GitLab repository an admin's token can see?(a) Only repositories listed by the admin. (b) Also every repository the token's user is a member of (ALL_MEMBER_PROJECTS).(b) is built, off by default, because LLD 4.1 says a scope is approved by a data owner before it is read. Decide who approves, and whether the admin's choice of (b) counts as that approval.Using (b) with real data.
D-14 openWhere does the admin enter the configuration?(a) Environment settings, as now. (b) The admin console's configuration API and UI.Both exist in this branch now. The console takes the same rules (no source mandatory, a selected one complete) and runs a configuration through the same ingestion path. Environment settings and the console are two ways to configure; decide which one is the source of truth for scheduled runs, because a console configuration is read once, in full, and is not scheduled.Scheduling console configurations.
D-15 openSSH keys for GitHub and GitLab: how are host keys trusted, and what is the key allowed to read?(a) Host keys known in advance: github.com and gitlab.com built in, other hosts from the operator (built). (b) Trust on first use. (c) Token only.(a) is built and is the only safe default: SSH works at once for github.com and gitlab.com (their published host keys are built in and match the vendors' published fingerprints), and a self-hosted host is refused until the operator adds its key. The check that the key really works runs when the admin submits the form (git ls-remote per repository). An SSH key cannot call the platform API, so with a key only the commit history is read (no pull requests, comments or reviews, and no list of repositories). The key is used for one run and not stored. The SSH path was tested against a local repository, not over a real SSH connection. Decide whether commit history alone is worth offering, and who owns the known-hosts list.Using SSH with real repositories.
D-16 openGitHub and ServiceNow are new sources: who approves their scopes, and what do they hold?As for Jira, GitLab and Confluence (LLD 4.1).Both are built, tested against recorded API shapes and not against live systems. ServiceNow journal comments and attachments live in other tables and are not read. Its integration user should be read-only. The ServiceNow logo in the UI is a placeholder (SN on green), not the vendor's mark.Live use.
D-17 openSaved results of each source, kept so a connector can be added to a configuration later.(a) Readable JSON next to the configuration (built). (b) Read the encrypted raw objects back through the index and the key.(a) is built because it is simple, but it is an unencrypted copy of what was read, like the run files. (b) keeps everything encrypted and is the right end state. The raw objects are stored in any case.Real data.
D-12 openMigrations (O-17).Alembic or another tool.The service creates its tables at start-up. Decide the tool before any shared database.Shared environments.
