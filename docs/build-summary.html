USEP ingestion layer and admin console

What was built, and why · 26 Nov 2026 · PoC modules 1 (UI and configuration) and 2 (ingestion) · mapped to the architecture reference and decisions register

In one line: a read-only layer that pulls Jira, GitLab, Confluence and Figma into one provenance-preserving format, plus an admin console that configures it, tests each connection, and shows a first knowledge graph. It is built and tested, but not yet run against live sources.

3Rules from the standards that were applied

  • Typed tokens are write-only: never stored, returned, logged or written to disk
  • Typed server addresses must be https; private and internal addresses blocked
  • Project keys and similar entries strictly validated (no query injection)
  • tenant_id on every configuration, checked on every read
  • Fails closed: no admin credentials set means nobody can sign in
  • Login rate-limited; raw sync and results endpoints now require sign-in
  • Audit events for login, logout, create, process, connection test, graph read
  • UUID v7 IDs, UTC timestamps, typed errors with a trace ID and no stack traces

5Decisions needed from you

  1. Figma: now blocked in the console and in the service until USEP_INGESTION_FIGMA_DPIA_APPROVED=true (ADR-025, O-05). Confirm who records that approval.
  2. Graph and failures: a configuration is ready only if every source the admin switched on was read; one failure of those means no graph. Keep this, or allow a partial graph with a visible warning? (Sources that were not switched on never count.)
  3. Jira window: approve adding the default 6-month window (row 4).
  4. Library ADR: who writes the single ADR confirming the framework set (row 5)?
  5. Gmail-style UI: does "like Gmail" mean matching how it works (search, labels with counts, bulk actions, shortcuts) or how it looks? Interaction parity is recommended.

6Status and housekeeping

Verification 63 + 23 tests pass
  • Backend: 63 tests (models, sync service, console API, URL guard, connection check). UI: 23 tests (validation, form model, router, graph model).
  • The full flow ran in a browser against the real API: sign-in, Test connection, submit, status, graph. The source data was faked.
  • Not verified: reading from real Jira, GitLab, Confluence or Figma. The ontology and evals checks from the “before every push” list were not run.
Where the code is partly uncommitted
  • Connectors are committed once, on branch ingestion-layer-connectors (initial codebase). The committed config has no credentials.
  • The console API and the reworked UI are uncommitted in the working tree on ontology-ui-graphify.
  • Still to do per the standards: a build record, Jira-key branch and commit names, and a pull request using the template.
